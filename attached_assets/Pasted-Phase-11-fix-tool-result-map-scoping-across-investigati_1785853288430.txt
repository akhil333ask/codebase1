Phase 11 — fix tool_result_map scoping across investigations in the same session.

Live evidence: in a session where the user asked a first question, got a full investigation with tool ids up to t-13, then asked a second, related question in the same session, the model correctly recalled and cited t-4 (a real get_code_snippet result from the first question, still visible to it in full_transcript/working_messages) — and check_verify_block rejected it with "not a tool result from this conversation." The id was real. The model wasn't hallucinating; the checker's notion of "this conversation" is narrower than the model's actual visible context.

Find where tool_result_map is initialized in start_interactive_chat (the un-truncated body of agent.py, likely near where next_tool_id and full_transcript are set up) and confirm whether it gets reset each time is_new_investigation is true for a new user question, while full_transcript and working_messages are not reset. If so, that's the bug: the model can see old tool results in its context but the harness won't accept citations against them.

Fix: make tool_result_map persist for the life of the whole session, not per-investigation — don't clear it when a new investigation starts, only ever add to it, so ids stay valid for as long as the model can actually see them in the transcript. next_tool_id should also keep incrementing across investigations rather than resetting, so ids stay unique and unambiguous across the whole session.

One thing to watch: if context.compact_if_needed ever folds early tool-result messages into a summary (Phase 1), the model may lose the ability to see the original t-N result text even though the id is still "valid" in tool_result_map. Check whether compaction and tool_result_map need to agree on what's still citable — if compaction has already summarized away a result, either evict its id from tool_result_map at the same time, or accept that a citation against a compacted-away id should fail with a clearer message than "not a tool result from this conversation" (e.g. "that result has since been summarized — re-fetch it if you need to cite it"). Don't guess which behavior is right without checking how compaction interacts with tool ids currently — flag it if the interaction isn't handled either way, rather than silently picking one.
